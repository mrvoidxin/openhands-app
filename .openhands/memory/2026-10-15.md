# 2026-10-15 - OpenHands mobile APK build

Repo `opanhand-mobile-` = a single `OpenHands-mobile.zip` (9.2 MB) containing
`OpenHands-main/`, the OpenHands Agent Canvas React/TS frontend
(`@openhands/agent-canvas` v1.27.1). No Android project in git; it is generated
at build time. `.github/workflows/build-android-apk.yml` is the reference recipe.

## Build recipe that works (verified)
1. JDK: `sudo apt-get install -y openjdk-21-jdk-headless`
   -> `/usr/lib/jvm/java-21-openjdk-amd64` (matches workflow's temurin 21).
2. Android SDK: cmdline-tools 11076708 into `/workspace/tools/android-sdk`,
   then `sdkmanager "platform-tools" "platforms;android-35" "build-tools;35.0.0"`.
   NOTE: extracted `cmdline-tools/latest/bin/*` arrive WITHOUT the exec bit ->
   `chmod +x` or `sdkmanager: Permission denied`.
3. `npm ci --ignore-scripts` (postinstall is just a global-install banner).
4. `VITE_MOCK_API=false npm run build:app` -> `build/` (~11 MB). Left
   `VITE_BACKEND_BASE_URL` UNSET so the UI shows its backend setup screen and
   the user supplies host+key at runtime. Mock worker is off (verified: entry
   chunks contain zero `mockServiceWorker` refs).
5. `npm install --no-save @capacitor/core@7 @capacitor/cli@7 @capacitor/android@7`
   then `npx cap add android` (copies build -> assets/public, 346 entries).
6. `./gradlew assembleDebug` / `assembleRelease` with JAVA_HOME + ANDROID_HOME.
   ~1m25s first (downloads gradle 8.11.1 + AGP 8.7.2), ~16s incremental.

## Gotchas worth remembering
- **`signingConfigs` must be declared BEFORE `buildTypes`** in
  `android/app/build.gradle`, else "Could not get unknown property 'release'".
- `storeFile file('release.keystore')` resolves relative to the MODULE dir, so
  the keystore belongs at `android/app/release.keystore`, not `android/`.
- Gradle wrapper needs a foreground-friendly timeout: runtime caps foreground
  commands at 1080s; run gradle with `nohup ... &` and poll the log.
- Icon: no ImageMagick/Inkscape; `pip install pillow` then downscale
  `electron/build-resources/icon.png` (1024x1024 master) into
  `mipmap-*/ic_launcher{,_round,_foreground}.png`. Foreground canvas is 108dp
  (mdpi 108 ... xxxhdpi 432) with the logo at ~62% so it survives the mask.
- Manifest has no `android:usesCleartextTraffic`; added
  `res/xml/network_security_config.xml` (https-only by default, cleartext for
  localhost/127.0.0.1/10.0.2.2) for self-hosted LAN agent servers.
- `@capacitor/android` compiles with SDK 35 / minSdk 23 -> already installed.

## Making the download link never go down (added later same day)
User asked for the link to never be down. Four independent layers, all in
`dl/` (plus hooks outside the repo):

1. **`supervisor.py`** — owns the HTTP servers on ports **12000 and 12001**
   (work-1 + work-2 = two independent links). Every 15s it checks the port and
   respawns `serve.py` if dead (recovers in ~5-15s, verified by killing both).
   Every 240s it pings the runtime to reset the 1200s idle timer. It also
   restores any missing APK from the durable backup.
2. **`watchdog.sh`** — every 60s, if `supervisor.py` is gone, runs
   `autostart.sh`. Covers a killed supervisor (verified: killed it, it came
   back in 60s).
3. **`.openhands/hooks.json`** `session_start` -> `dl/autostart.sh` — restarts
   the stack after a sandbox reset/wake. Written to BOTH
   `/workspace/project/.openhands/` and
   `/workspace/project/opanhand-mobile-/.openhands/` because the workspace root
   could be either (PID 1 cwd is `/workspace/project`). Verified the
   agent-server parses it: `POST /api/hooks {"project_dir": ...}` returns the
   hook. `autostart.sh` is idempotent (no-ops if the supervisor is alive).
4. **Durable backup** `/workspace/artifacts/openhands-apk/*.apk` outside the
   repo, so a wiped checkout cannot lose the artifact.

Verified all four by deliberately killing servers, the supervisor, and deleting
an APK. Port 12001 was initially held by a leftover `sirv` preview server from
the earlier UI check — the supervisor waits for the port and then binds it.

## PERMANENT hosting solved: GitHub Releases (2026-10-15)
The user supplied a **classic PAT with `repo` + `workflow` scope** (`ghp_...`),
which finally allowed publishing. Stored at `~/.gh_pat` (chmod 600) — never put
it in a command line; use
`git -c credential.helper='!f() { echo username=mrvoidxin; echo password=$(cat ~/.gh_pat); }; f'`
and for API calls read the file from Python.

**Live permanent links:**
- https://github.com/mrvoidxin/opanhand-mobile-/releases/latest/download/app-release.apk
- https://github.com/mrvoidxin/opanhand-mobile-/releases/latest/download/app-debug.apk
- release page: .../releases/tag/v1.27.1

**Why the old token failed and this one works.** `ghu_...` = GitHub App *user
access token*, granted read-only (403 "Resource not accessible by integration"
on every write, even though the repo object misleadingly reports
`permissions.push=true`). A classic `ghp_...` PAT with `repo` scope works.
Also: `git remote` had the old token **embedded in the URL**, which overrode
any credential helper — `git remote set-url origin https://github.com/OWNER/REPO.git`
first.

**Why Actions had never run.** The repo root contained only
`OpenHands-mobile.zip` + `README.md`; `.github/workflows/build-android-apk.yml`
was *inside the zip* (`OpenHands-main/.github/workflows/`). **GitHub Actions only
reads workflows from the repository root.** Moved the workflow to
`/.github/workflows/build-android-apk.yml` and committed the Capacitor
`android/` project source so CI can build it.

**CI gotchas found the hard way:**
1. `android-actions/setup-android@v3` FAILS on ubuntu-latest — it tries to
   install the long-removed `tools` package (`Failed to find package 'tools'`),
   which aborts the job. The runner already has the SDK; drop the step.
2. `npx cap sync` fails with `could not determine executable to run` because
   @capacitor packages are **not** in package.json (installed with `--no-save`
   locally). CI must `npm install --no-save @capacitor/core@7 @capacitor/cli@7
   @capacitor/android@7` first.
3. Only `aapt2` exists in build-tools 35, not `aapt`.
4. `npm run build:app` regenerates i18n, so the gitignored `public/locales` is
   fine in CI.

**DRAFT-RELEASE TRAP (cost time to debug):** deleting and re-pushing a tag that
already had a release turns that release into a **draft**, and draft asset URLs
become `untagged-<hash>` and 404. Fix: `PATCH /releases/<id>` with
`{"draft": false}`. CI's `gh release create/upload` succeeded but the release
stayed invisible until published.

**Repo layout now:** repo root holds `.github/workflows/`, `.gitignore`,
`OpenHands-main/` (source + android/), `dl/` (local serving scripts), `.openhands/`.
CI-built release APK md5 `2365d6465759187c4c5a6716c2219242` (6,257,650 bytes) —
slightly different from the local build because CI rebuilds the web bundle.

### The `ghu_` token could not publish (superseded by the PAT above)
Kept for reference: every write returned 403 "Resource not accessible by
integration" (`POST /releases`, `/git/refs`, `/gists`, `/issues`) and
`GET /user/installations` -> `total_count: 0`. The repo object *advertises*
`permissions: {admin, maintain, push, triage, pull}` because that is the owner's
own access, which is misleading — the token's actual grant is what matters.
Reads work fine (5000/hr).

`dl/publish-github.sh` is ready and self-diagnosing: it probes write access
first and, if it fails, prints the two fixes. Run
`GH_PAT=<writable-token> bash dl/publish-github.sh` once a token with `repo`
scope (classic) / `Contents: Read and write` (fine-grained) is available, or
grant the OpenHands GitHub App "Read and write" on the repo and re-run with the
refreshed `GITHUB_TOKEN`. It creates tag `v1.27.1` and uploads
`app-release.apk` + `app-debug.apk` to
`https://github.com/mrvoidxin/opanhand-mobile-/releases/latest` (permanent URL).
