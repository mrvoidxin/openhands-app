## APK fact-check: trust androguard, not a hand-rolled parser
I wrote a custom v2 signing-block parser and it produced a wrong fingerprint
(`f2:a2:...`) for both APKs — a bug in my parsing, not in the APK. `androguard`
gave the right answer for both the local build and the release asset:

    local   META-INF/CERT.RSA -> 0D:96:FA:45:...:81:12  (CN=OpenHands Mobile)

## Signing key pinned so updates install in place (2026-10-16)
- Commit `8fddf55`. User requirement: future APK updates must use the SAME
  signing key, so users never uninstall - a straight update must always work.
- **The repo already did this by accident, not by design.** The CI secret
  holds a 2742-byte PKCS12 keystore; CI log says `keystore restored: 2742
  bytes`. A rotated secret would have silently published an APK Android
  refuses to install over the app, forcing every user to uninstall.
- **Pinned signer (public, ships inside every APK, safe to commit):**
  `0D:96:FA:45:8C:34:42:D2:28:AC:C8:56:97:04:10:4A:4E:83:44:3A:68:0E:DF:81:C6:AE:0D:D1:6D:DA:81:12`
  subject `CN=OpenHands Mobile,OU=Agent Canvas,O=OpenHands,C=IN`,
  self-signed, valid 2026-10-15 -> 2054-03-02. v1.27.2 and v1.27.3 have the
  identical cert, so v1.27.2+ users already update in place.
- To re-verify a keystore/cert WITHOUT a JDK (no keytool in this sandbox):
  the password is unknown, so instead parse the APK. `META-INF/CERT.RSA` is
  PKCS#7 - `cryptography.hazmat.primitives.serialization.pkcs7.
  load_der_pkcs7_certificates` reads it. Script: `/tmp/ksinfo.py`,
  `/tmp/apksig.py`. This is how the v1.27.2/v1.27.3 certs were compared.
- **CI gate** in `.github/workflows/build-android-apk.yml`, inside the
  `Verify the release APK` step: reads the signer SHA-256, compares to the
  pinned value, `::error::SIGNING KEY CHANGED` + `exit 1` on mismatch.
  Must be robust to BOTH output formats: apksigner prints bare 64-hex
  (`Signer #1 certificate SHA-256 digest: 0d96fa...`), keytool prints
  colon-separated. Normalise with `tr -d ':' | tr 'a-f' 'A-F' |
  sed 's/\(..\)/\1:/g; s/:$//'`. It fails CLOSED when neither format is
  found. Gate is inside `if [ "$KEYSTORE_WAS_RESTORED" = "true" ]`, so
  unsigned branch/PR runs stay green.
- Escape hatch: `SIGNING_CERT_SHA256` repo *variable* overrides the pin, so a
  deliberate rotation needs no workflow edit. Documented in `SIGNING.md`
  (new) and the README settings table.
- README: replaced the now-historical "uninstall first if older than v1.27.2"
  block with the in-place guarantee.
- **Landing page** corrected from v1.27.2 to the current release: v1.27.3,
  6,456,583 bytes, SHA-256 `5640e965f98712bc4967c576e242af250b3f066a80ec693bc346
  511ce3fcbf62`. README already had the right v1.27.3 numbers; only the page
  was stale. The two remaining "v1.27.2" mentions are intentional (the
  "from v1.27.2 on" guarantee).
- CI verified green: `signer fingerprint` and `expected fingerprint` printed
  identical, then `signing key matches the pinned fingerprint`.
- **Fragility to remember:** GitHub Actions Android builds are NOT
  reproducible - two builds of the same commit gave different APK SHA-256
  (`5640e965` vs `71bb2378`, same 6,456,583 bytes). The published release
  asset is only replaced on a `v*` tag push, so `releases/latest/download/...`
  keeps the asset the page hash describes. Re-tagging an existing version
  would clobber it and break the advertised hash. Bump the version instead.

## OpenHands Mobile landing page — screenshot overlap fix (2026-10-16, cont.)
- Active ask: added images "looked wrong, word ke uper word". Committed
  `docs/assets/screens/0{1..4}.webp` were all near-identical stacked slides.
- **Root cause (two parts, both expensive):**
  1. The wizard slides are composited: all N slides live as siblings inside
     `.overflow-clip` with `transform: translateX(±100%)`. `getBoundingClientRect`
     of a slide returns the *viewport* box (transformed), so screenshotting the
     slide element directly still shows whatever overlaps. Fixed by forcing each
     sibling's inline transform to `translateX((j-idx)*100%)` before capture —
     no animation, instant jump, all other slides fully offscreen.
  2. A telemetry consent card (`[data-testid=telemetry-consent-form]`,
